## Checks that came back clean

- **No heavy SDK leak in public headers.** No OpenColorIO, Slang, OpenImageIO,
  Diligent or USD header appears under `include/sigilmaterial/` (verified by
  enumerating every `#include` in all 45 public headers). `ocio/Ocio.h` and
  `slang/SlangCompiler.h` name none of their vendor's types.
- **README API names all exist.** Every `` `name()` `` spelled in README.md
  resolves to a declaration in a header or a definition in a .cpp (405 back-ticked
  identifiers checked; only `sigil_shader_sources` is a CMake function, which
  exists at `cmake/Sigil.cmake:413`).
- **Comment-rule grep clean** for TODO/FIXME/XXX/HACK, dates, "renamed",
  "used to be", "previously", "legacy", "campaign", "phase N", performance
  numbers, and `std::cout`/`printf`/`qDebug` in library code. All diagnostics go
  through `SkDebugf` or `reportOnce`. The four citation violations above are the
  only comment-rule failures found.
- **Slang compile path is thread-safe**: `compileModule` (slang/SlangCompiler.cpp:172)
  holds a mutex across the session lookup and the module load.
- **ProgramCache** in-flight/generation handling, `Recipe::relayout` idempotence,
  `Dither::threshold` bounds (matrix 1..16, negative coordinates, levels < 2),
  `Palette::at`/`nearest` clamping, `Extract`'s empty/single-colour/k>distinct
  behaviour under KMeans, `faceOf`'s cube-face orientation, `boxBlurF32`'s wrap
  and clamp windows, and `Atlas`'s simdjson short-circuits were all read and are
  correct.
